# Спецификация ПО: консольный тренажёр грамматики иностранного языка

## 1. Назначение и общая концепция

Консольное приложение для изучения грамматики иностранного языка. Приложение показывает фразу на родном языке (`native`) и запрашивает её перевод на изучаемый язык (`foreign`), оценивает ответ, подсвечивает ошибки и планирует последующие показы по алгоритму интервального повторения FSRS.  

Ключевые принципы:
- Простое, аскетичное консольное приложение.  
- Разбиение по архитектурным слоям не требуется.  
- Направление перевода универсально: в коде — `native`/`foreign`, конкретные языки задаются в конфиге. `native` всегда слева в `phrases.txt`.  

## 2. Целевая платформа и зависимости

- Python: 3.12  
- Внешние библиотеки:  
  - `py-fsrs` — планирование повторений (используется в ядре);  
  - `colorama` — раскраска вывода в CLI (в адаптере UI);  
  - `PyYAML` — чтение/запись конфига;  
  - `jellyfish` — расчёт расстояния Левенштейна;  
  - библиотека `difflib` или собственный Levenshtein-backtrace — для выравнивания при подсветке (на усмотрение реализации).  
- Ограничений по зависимостям нет.  
- Тесты на данном этапе не требуются.  

## 3. Формат `phrases.txt`

### 3.1. Синтаксис

- Кодировка: UTF-8 без BOM.  
- Одна фраза = одна строка.  
- Разделитель между native и блоком переводов: `||` (двойная вертикальная черта).  
- Разделитель между вариантами перевода: `|` (одинарная).  
- Пример: `Мы помним это || We remember it | We remember this`  
- Комментарии: символ `#`. Допустимы как строки-комментарии целиком, так и inline-комментарии в конце строки (всё от `#` до конца строки отбрасывается и не обрабатывается).  
- Пустые строки допустимы (игнорируются).  

### 3.2. Нормализация при разборе

- Пробелы вокруг `||` и `|` не важны, фразы либо могут быть отделены от `||` и `|` пробелом, либо нет.  
- Пробелы нормализуются: обрезка краёв сегментов + схлопывание множественных внутренних пробелов в один.  

### 3.3. Идентификация фразы

- Уникальный идентификатор карточки — текст native-части (левая часть до `||`, после нормализации).  

### 3.4. Ошибки → прерывание выполнения

При любой из следующих ошибок программа выводит сообщение с номерами строки и характерами ошибок и завершается:  
- отсутствует `||`;  
- более одного `||` в строке;  
- пустая native-часть;  
- все варианты перевода пусты;  
- пуст хотя бы один из вариантов (например `A | | B`);  
- дубликат native-фразы (две строки с одинаковой native-частью).  

### 3.5. Пустой набор

Если после разбора нет ни одной фразы (только комментарии/пустые строки) — сообщение «нет фраз для изучения» и выход. Аналогично, если `user.json` пуст после синхронизации или пуст после всех подтвержденных удалений.  

## 4. Хранилище `user.json`

### 4.1. Общие требования

- Хранится разумное количество данных (даже те данные, которые не требуются прямо сейчас, могут пригодится после смены пользовательского интерфейса или методики определения следующей карточки).  
- Обновляется атомарно (временный файл в той же папке, что и user.json + `os.replace()`).  
- Содержит версию схемы для будущих миграций.  
- Все timestamps — в UTC, формат ISO 8601. «Due/сегодня» вычисляется по UTC.  
- При повреждении/невалидности — сообщение пользователю и запрос подтверждения на пересоздание (через `confirm`); при согласии — бэкап старого файла и создание нового.  
- Защита от параллельного запуска не требуется.  

### 4.2. Структура (концептуально)

```json
{
  "schema_version": 1,
  "cards": {
    "<native_text>": {
      "native": "Мы помним это",
      "foreign_variants": ["We remember it", "We remember this"],
      "first_show": true,
      "fsrs_state": { /* сериализованное состояние карточки py-fsrs */ },
      "created_at": "2025-01-01T12:00:00Z",
      "last_shown_at": "2025-01-05T09:30:00Z",
      "counters": {
        "shows": 12,
        "success": 9,
        "fail": 3
      },
      "history": [
        {
          "timestamp": "2025-01-05T09:30:00Z",
          "user_input": "we remember it",
          "chosen_reference": "We remember it",
          "distance": 0,
          "rating": "Easy"
        }
        /* FIFO, максимум 30 записей; при переполнении удаляется самая старая */
      ]
    }
  }
}
```

Поля:  
- `foreign_variants` — полный список вариантов перевода (хранится для сравнения; синхронизируется с `phrases.txt` при старте, `phrases.txt` - важнее, это первоисточник).  
- `first_show` — флаг обучающего показа.  
- `history` — FIFO-буфер длиной 30; одна запись на предъявление карточки (по первому вводу). Повторы (мышечная память) в FIFO не пишутся.  

## 5. Синхронизация `phrases.txt` -> `user.json` (при старте)

Приоритет — `phrases.txt`. Идентификация по native-тексту.  

| Событие в phrases.txt | Действие в user.json |
|---|---|
| Добавлена новая native-фраза | Создать карточку, `first_show = true`, инициализировать FSRS-состояние |
| Удалена native-фраза | Запросить подтверждение у пользователя; при согласии — удалить карточку безвозвратно |
| Изменена native-фраза | Трактуется как удаление старой + добавление новой |
| Изменён/добавлен/удалён вариант перевода (при той же native) | Коррекция `foreign_variants`, статистика FSRS и флаг first_show сохраняются |
| Переставлен порядок вариантов | Коррекция без сброса статистики и флага |

- Порядок новых карточек для предъявления определяется по позиции в `user.json` при старте.  
- Бэкап всего файла делается только при повреждении (не при штатном удалении карточек).  

## 6. Логика учебной сессии

### 6.1. Выбор следующей карточки

1. Приоритет — due-карточки (срок повторения по FSRS наступил, UTC). Пока есть due — выдаём их.  
2. Когда due нет — вероятностная схема 50/50 на каждом шаге: с вероятностью 50% берём одну ближайшую по времени будущего повторения (досрочно), с вероятностью 50% — одну новую (в порядке из `user.json`). Если досрочных задач нет, берем 100 % новые, если новых нет - берем 100 % досрочные.  
3. Когда нет due и все новые исчерпаны — fallback по FIFO-истории: приоритет карточкам с бОльшей давностью показа.  

- При отсутствии due сообщать пользователю, что срочных повторений нет, и продолжать обучение.  
- Лимита новых карточек за сессию нет.  

### 6.2. Обычный показ карточки

1. Показать native-фразу + приглашение к вводу (аскетично, без служебной информации).  
2. Пользователь вводит перевод.  
3. Нормализация ввода и эталонов перед сравнением:  
   - привести к нижнему регистру;  
   - проверить на команду `/exit`
   - убрать пунктуацию (в т.ч. дефис и апостроф — их можно не вводить);  
   - символы табуляции превратить в пробелы, объединить множественные пробелы, обрезать края.  
4. Из всех корректных вариантов выбирается ближайший по `jellyfish.levenshtein_distance`. При равном расстоянии — первый по порядку. Дальнейшая работа — с выбранным эталоном.  
5. Вычислить рейтинг по первому вводу.  
6. Показать эталон (в оригинальном регистре и с пунктуацией) с подсветкой ошибок.  
7. Обновить данные и сохранить `user.json` сразу после первого ввода: рейтинг передаётся в FSRS, обновляются счётчики, `last_shown_at`, добавляется запись в FIFO. Повторы на данные не влияют.  
8. Если рейтинг хуже Easy — запускается цикл повторного ввода (см. 7.3), но он уже не меняет данные.  
9. По достижении Easy — сразу следующая карточка (без промежуточного экрана).  

### 6.3. Цикл повторного ввода (мышечная память)

- Запускается при любом ответе хуже Easy (Good / Hard / Again).  
- Повторы не влияют на рейтинг FSRS (он зафиксирован по первому вводу), не пишутся в FIFO, но пишутся в общий лог.  
- Повторы не триггерят сохранение `user.json`.  

### 6.4. Шкала рейтингов (пороги в конфиге)

Оценка по расстоянию Левенштейна между нормализованными вводом и эталоном; границы Good/Hard — по проценту от длины эталона (пороги задаются в конфиге):  
- Easy — 0 или 1 ошибка;  
- Good — ошибок от 2 до 4;  
- Hard — ошибок от 5 до 8;  
- Again — больше 8 ошибок.  

Веса модели FSRS — дефолтные.  

### 6.5. Подсветка ошибок

- Diff строится на нормализованном сравнении, но результат накладывается на оригинальный эталон (регистр + пунктуация).  
- Выравнивание символов — LCS/Levenshtein-diff (инструмент на усмотрение).  
- Пометки сегментов в UI:  
  - ошибочный/лишний символ → красный;  
  - пропущенный или лишний пробел → красный символ `_`;  
  - знаки пунктуации в эталоне (игнорируемые при сравнении) → нейтральный цвет (не ошибка).  

### 6.6. Первый показ (обучающий)

- Условие: `first_show == true` (по отдельному флагу, не по данным FSRS).  
- Показывается native + правильный foreign (первый вариант из `phrases.txt`) — до ввода.  
- Пользователь вводит перевод для тренировки.  
- Подсветка ошибок выполняется как обычно, сравнение — с ближайшим вариантом (единообразно с обычным показом).  
- При ошибке хуже Easy — запускается тот же цикл повторного ввода.  
- В FSRS/счётчики/FIFO/даты первый показ не пишется — влияет только на флаг `first_show`.  
- Флаг `first_show` снимается только после доведения ввода до Easy. Сохранение `user.json` на первом показе — после успешного завершения (Easy), тогда же фиксируется снятие флага. Если пользователь вышел через `/exit` до достижения Easy — флаг остаётся `true` до следующего запуска.  

## 7. Команды и завершение

- Выход — команда `/exit`, распознаётся на любом этапе ввода. Об этом сообщается пользователю при старте.  
- Фраз, начинающихся с `/`, не предполагается (конфликтов нет).  
- `/exit` посреди цикла повторного ввода — просто выход; данные по первому вводу уже сохранены (обычный показ) либо не сохранены (первый показ, если Easy не достигнут).  
- Иных служебных команд нет: пользователь последовательно нажимает Enter.  

## 8. Конфигурация (YAML)

- Формат: YAML.  
- При отсутствии — создаётся дефолтный конфиг.  
- Содержит (как минимум):  
  - пути к `phrases.txt` и `user.json`;  
  - имя пользователя;  
  - названия языков `native` и `foreign` (используются в подсказках, напр. «Переведите на {foreign}:»);  
  - все интерфейсные строки с плейсхолдерами (`str.format`, напр. `"Привет, {user}! Для выхода введите /exit"`);  
  - пороги рейтингов FSRS (границы Good/Hard в процентах, порог Again);  
  - параметры FSRS: `desired_retention`, `maximum_interval`;  
  - логирование: размер файла, число backup-файлов, уровень логирования.  

## 9. Логирование

- Кольцевой лог через `RotatingFileHandler`.  
- Размер файла и число backup-файлов — в конфиге.  
- Уровень логирования — в конфиге.  
- Логируется всё: старт, синхронизация (добавления/удаления/коррекции), каждый ответ пользователя со статистикой, повторные вводы, ошибки.  

## 10. Поток выполнения при старте

1. Загрузка/создание конфига (YAML). Если загруженный конфиг невалиден, сообщаем пользователю, выходим из программы.  
2. Инициализация логирования.  
3. Чтение и валидация `phrases.txt`; при ошибке — сообщение (с номером строки) и выход.  
4. Загрузка `user.json`; при повреждении — сообщение + запрос подтверждения на пересоздание (бэкап + новый файл).  
5. Синхронизация `phrases.txt` → `user.json` (с подтверждением удалений).  
6. Проверка на пустой набор карточек → при пустоте сообщение и выход.  
7. Приветствие + инструкция про `/exit` + легенда цветов подсветки (красный = ошибка, `_` = пропущенный/лишний пробел).  
8. Цикл учебной сессии до `/exit`.  

## 11. Сводка ключевых инвариантов  

- Идентификатор карточки — нормализованный native-текст.  
- Изменение native = удаление + создание; изменение переводов = коррекция без потери статистики.  
- Рейтинг фиксируется по первому вводу; повторы — только для мышечной памяти.  
- Обычный показ: сохранение сразу после первого ввода. Первый показ: сохранение только после достижения Easy (снятие флага).  
- Сравнение всегда с ближайшим вариантом; при равенстве — первый.  
- Все времена — UTC.
