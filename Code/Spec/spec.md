# Спецификация ПО: консольный тренажёр грамматики иностранного языка  
Версия спецификации: 2.0.  
  
## 1. Назначение и общая концепция  
  
Консольное приложение для изучения грамматики иностранного языка. Приложение показывает фразу на родном языке и запрашивает её перевод на изучаемый язык, сравнивает ответ с допустимыми вариантами, подсвечивает расхождения и планирует повторения с помощью FSRS.  
  
В коде используются обозначения `native` и `foreign`. Конкретные языки задаются в конфиге. В `phrases.txt` родной язык всегда расположен слева.  
  
### 1.1. Ключевые принципы  
  
- Аскетичный консольный интерфейс без лишней служебной информации.  
- Чистая архитектура: бизнес-логика не зависит от CLI, файловой системы, YAML и конкретной библиотеки планирования.  
- `phrases.txt` — первоисточник состава карточек и допустимых переводов.  
- Результат обычного предъявления фиксируется по первому вводу. Последующее перепечатывание его не меняет.  
- Плановое повторение и досрочная практика — разные типы событий. Только плановое повторение обновляет FSRS.  
- Успешно принятый результат немедленно сохраняется. При ошибке сохранения сессия не продолжается.  
- Все сохраняемые даты и вычисления сроков используют UTC.  
  
### 1.2. Ограничения методики  
  
Приложение проверяет близость к заданным переводам, а не грамматическую корректность произвольного ответа. Корректный перевод, отсутствующий среди вариантов, может быть оценён как ошибочный.  
  
Посимвольное сравнение не отличает опечатку от грамматической ошибки. Автоматическое преобразование результата сравнения в рейтинг FSRS является эвристикой.  
  
Нормализация не гарантирует одинаково корректную обработку всех языков. Политика пунктуации задаётся явно и не должна подразумеваться из названия языка.  
  
## 2. Целевая платформа и зависимости  
  
- Python 3.12.  
- Библиотека FSRS для Python — за адаптером планировщика. Конкретный пакет и его версия фиксируются в зависимостях проекта.  
- `colorama` — цветной вывод CLI.  
- `PyYAML` — безопасная загрузка и запись конфига.  
- `jellyfish` — вычисление расстояния Левенштейна.  
- Собственный Levenshtein-backtrace — получение операций выравнивания для подсветки.  
- Стандартная библиотека Python — JSON, логирование, файловые операции, даты и время.  
  
Дополнительные зависимости допускаются при обоснованной необходимости. Версии прямых зависимостей фиксируются.  
  
Автоматические тесты не входят в обязательный объём первой версии. Приёмочные сценарии из §17 обязательны для ручной проверки.  
  
## 3. Архитектура  
  
### 3.1. Слои  
  
```text  
Адаптеры  
├── CliAdapter  
├── PhrasesFileAdapter  
├── UserJsonRepository  
├── YamlConfigLoader  
├── FsrsSchedulerAdapter  
├── SystemClock  
├── RandomAdapter  
└── LoggingAdapter  
          │  
          │ интерфейсы приложения  
          ▼  
Прикладной слой  
├── StartupService  
├── SyncService  
├── StudySession  
└── CardSelector  
          │  
          ▼  
Домен  
├── Card  
├── UserData  
├── AnswerComparator  
├── Normalizer  
├── DiffBuilder  
└── модели событий и результатов  
```  
  
Интерфейсы портов принадлежат внутренним слоям. Адаптеры реализуют эти интерфейсы.  
  
Объекты библиотеки FSRS не передаются в CLI и не используются непосредственно в сценарии учебной сессии. Сериализация и восстановление библиотечных объектов выполняются адаптером планировщика.  
  
### 3.2. Порт UI  
  
```python  
class UserInterface:  
    def show_message(self, text: str) -> None: ...  
    def prompt_input(self, prompt: str) -> InputResult: ...  
    def show_diff(self, result: DiffResult) -> None: ...  
```  
  
`InputResult` содержит либо сырой текст, либо сигнал завершения ввода: `EOF` или `INTERRUPT`.  
  
CLI не распознаёт `/exit` и не принимает бизнес-решений. Обработка команд и интерпретация подтверждений выполняются в прикладном слое.  
  
Подтверждение реализуется через тот же `prompt_input()`. Допустимые ответы после `strip().casefold()`:  
  
- `y`, `yes` — согласие;  
- `n`, `no` — отказ;  
- `/exit` — завершение приложения.  
  
При ином ответе вопрос повторяется.  
  
В первой версии сценарий взаимодействия синхронный и блокирующий. Возможность подключения web-интерфейса не означает гарантированной замены CLI без изменения управления сессией.  
  
### 3.3. Порт фраз  
  
```python  
class PhraseRepository:  
    def load(self) -> list[ParsedPhrase]: ...  
```  
  
Адаптер читает файл и выполняет синтаксическую проверку. Доменные правила нормализации предоставляются ядром.  
  
При ошибках возвращается или выбрасывается агрегированная ошибка с общим числом проблем и ограниченным списком диагностик. Каждая диагностика содержит номер строки, код и описание.  
  
Для дубликата указываются номер текущей строки и номер первого определения.  
  
### 3.4. Порт пользовательских данных  
  
```python  
class UserDataRepository:  
    def load(self) -> UserData | None: ...  
    def save(self, data: UserData) -> None: ...  
    def backup(self) -> BackupInfo: ...  
```  
  
`None` означает отсутствие файла, но не пустой или повреждённый файл.  
  
Ошибки загрузки разделяются на:  
  
- повреждение JSON или нарушение поддерживаемой схемы;  
- неподдерживаемую версию схемы;  
- неподдерживаемую версию состояния планировщика;  
- ошибки доступа и ввода-вывода.  
  
### 3.5. Порт планировщика  
  
```python  
class SchedulerPort:  
    def first_review(self, rating: Rating, reviewed_at: datetime) -> ScheduleResult: ...  
    def review(  
        self,  
        state: SchedulerState,  
        rating: Rating,  
        reviewed_at: datetime,  
    ) -> ScheduleResult: ...  
    def validate_state(self, state: SchedulerState) -> None: ...  
```  
  
`ScheduleResult` содержит:  
  
- новое сериализуемое состояние;  
- следующий срок повторения `due_at`;  
- сериализуемые данные события планировщика.  
  
`first_review()` создаёт новую библиотечную карточку на момент первой проверки и применяет к ней первый рейтинг. Обучающий показ до этого не считается review-событием FSRS.  
  
### 3.6. Прочие зависимости  
  
- `Clock.now() -> datetime` — текущее timezone-aware время UTC.  
- `RandomPort.random() -> float` — случайное число в диапазоне `[0, 1)`.  
- `LoggerPort` — запись структурированных событий.  
- Валидированный неизменяемый объект конфигурации передаётся сценариям при создании. Постоянное чтение YAML из бизнес-логики не допускается.  
  
## 4. Формат `phrases.txt`  
  
### 4.1. Синтаксис  
  
- Кодировка UTF-8 без BOM. BOM считается ошибкой формата.  
- Одна карточка занимает одну строку.  
- Разделитель родной фразы и переводов: `||`.  
- Разделитель вариантов перевода: `|`.  
- `#` начинает комментарий; всё от него до конца строки отбрасывается.  
- Пустые строки и строки-комментарии игнорируются.  
- Экранирования нет. Символы `#` и `|` зарезервированы и не могут быть частью текста фразы.  
  
Пример:  
  
```text  
# Примеры  
Мы помним это || We remember it | We remember this  
Она работает дома || She works at home # Present Simple  
```  
  
### 4.2. Разбор разделителей  
  
После удаления комментария:  
  
1. Последовательности из трёх и более подряд идущих `|` считаются ошибкой.  
2. В строке должен присутствовать ровно один разделитель `||`.  
3. Одиночный `|` в левой части запрещён.  
4. Правая часть разделяется по одиночному `|`.  
  
`A || B | | C` содержит пустой вариант перевода и является ошибкой.  
  
### 4.3. Нормализация отображаемого текста  
  
Для native-фразы и каждого варианта перевода:  
  
1. Применяется Unicode NFC.  
2. Последовательности whitespace-символов заменяются одним обычным пробелом.  
3. Пробелы по краям удаляются.  
  
Регистр и пунктуация сохраняются для показа.  
  
### 4.4. Идентификатор карточки  
  
Хранятся два значения:  
  
- `native` — нормализованный отображаемый текст;  
- `native_key` — результат `casefold()` для `native`, повторно приведённый к NFC.  
  
`native_key` является уникальным идентификатором карточки. Пунктуация из него не удаляется.  
  
Следствия:  
  
- изменение только регистра или количества пробелов не создаёт новую карточку;  
- изменение слов или пунктуации может изменить ключ и трактуется как удаление старой карточки и добавление новой.  
  
### 4.5. Ошибки  
  
Файл полностью проверяется до изменения пользовательских данных. Ошибками являются:  
  
- нарушение кодировки;  
- отсутствие или избыток разделителей;  
- недопустимая последовательность `|`;  
- пустая native-часть;  
- пустой вариант перевода;  
- вариант перевода, пустой после нормализации для сравнения;  
- дубликат `native_key`;  
- превышение ограничений длины или количества вариантов из конфига.  
  
Совпадение двух переводов после нормализации для сравнения допускается. Выдаётся предупреждение; варианты сохраняются в исходном порядке.  
  
При любой ошибке запуск прекращается. Показывается не более `max_phrase_errors` диагностик. Если ошибок больше, выводится общее число и сообщение о непоказанных ошибках.  
  
### 4.6. Пустой файл  
  
Если после разбора нет ни одной карточки, приложение выводит «Нет фраз для изучения» и завершается **до загрузки и изменения `user.json`**.  
  
Пустой файл не используется как команда массового удаления прогресса.  
  
## 5. Нормализация и сравнение ответов  
  
### 5.1. Порядок обработки  
  
Пользовательский ввод сначала проверяется на команду завершения. Только после этого выполняется нормализация ответа.  
  
Нормализация для сравнения:  
  
1. Unicode NFC.  
2. `casefold()`.  
3. Повторная Unicode NFC.  
4. Замена whitespace-символов обычными пробелами.  
5. Обработка пунктуации согласно конфигу.  
6. Схлопывание пробелов и обрезка краёв.  
  
Числа, диакритические знаки и символы, не относящиеся к пунктуации, автоматически не удаляются.  
  
Табуляция становится пробелом, а не склеивает соседние слова.  
  
### 5.2. Политика пунктуации  
  
Поддерживаются три режима:  
  
- `strict` — пунктуация сохраняется;  
- `selected` — применяется набор явных преобразований и список игнорируемых символов;  
- `ignore_all` — удаляются символы Unicode-категорий пунктуации `P*`.  
  
По умолчанию используется `selected`:  
  
- `. , ! ? : ; …` игнорируются;  
- типографские апострофы приводятся к `'`;  
- распространённые варианты дефиса приводятся к `-`;  
- апострофы и дефисы после преобразования сохраняются.  
  
Преобразования символов выполняются до удаления игнорируемых символов. Точная таблица преобразований хранится в конфиге.  
  
Таким образом, при настройках по умолчанию `we'll` и `well` не совпадают.  
  
Режим `ignore_all` доступен как сознательное упрощение и сопровождается описанием риска слияния разных форм.  
  
### 5.3. Выбор эталона  
  
Для каждого варианта вычисляется расстояние Левенштейна между нормализованным ответом и нормализованным переводом.  
  
Выбирается вариант с минимальным абсолютным расстоянием. При равенстве выбирается первый по порядку в `phrases.txt`.  
  
Это правило применяется независимо к каждому вводу, в том числе при перепечатывании. Выбранный вариант может измениться между попытками.  
  
В историю предъявления записывается только вариант, выбранный для первого ввода.  
  
### 5.4. Единицы сравнения  
  
Расстояние и длина вычисляются в кодовых точках Python-строк после нормализации. Сегментация на графемы в первой версии не выполняется.  
  
Для выбранного эталона:  
  
```text  
d = расстояние Левенштейна  
L = длина нормализованного эталона  
r = d / L  
```  
  
`L > 0` гарантируется проверкой фраз. `r` может превышать 1.  
  
### 5.5. Категории результата  
  
Категории точности отделены от рейтингов FSRS.  
  
Правила применяются последовательно:  
  
| Условие | Категория |  
|---|---|  
| Нормализованный ответ пуст | `incorrect` |  
| `d == 0` | `exact` |  
| `d <= near_max_edits` и `L >= near_min_reference_length` | `near` |  
| `r < partial_max_ratio` | `partial` |  
| Иначе | `incorrect` |  
  
Значения по умолчанию:  
  
```yaml  
near_max_edits: 1  
near_min_reference_length: 10  
partial_max_ratio: 0.20  
```  
  
`near` означает небольшое посимвольное отличие, но не гарантированную опечатку.  
  
### 5.6. Преобразование в рейтинг FSRS  
  
По умолчанию:  
  
| Категория | Рейтинг FSRS |  
|---|---|  
| `exact` | `Good` |  
| `near` | `Hard` |  
| `partial` | `Hard` |  
| `incorrect` | `Again` |  
  
Точный ответ автоматически не означает лёгкого припоминания, поэтому `Easy` по умолчанию не назначается.  
  
Таблица преобразования задаётся в конфиге. Допускаются только известные рейтинги FSRS. Категория `incorrect` всегда должна соответствовать `Again`.  
  
Изменение таблицы влияет только на будущие ответы. История и ранее рассчитанное расписание не пересчитываются.  
  
### 5.7. Завершение перепечатывания  
  
Условие завершения не зависит от названия рейтинга FSRS:  
  
- при `accept_near_for_completion: false` принимается только `exact`;  
- при `accept_near_for_completion: true` принимаются `exact` и `near`.  
  
По умолчанию требуется `exact`, поскольку тренажёр предназначен для грамматики.  
  
## 6. Подсветка ошибок  
  
### 6.1. Выравнивание  
  
Выравнивание строится алгоритмом Levenshtein-backtrace с теми же стоимостями операций, что используются при вычислении расстояния: вставка, удаление и замена стоят 1.  
  
При нескольких оптимальных путях используется фиксированный порядок предпочтения:  
  
1. Совпадение.  
2. Замена.  
3. Пропуск символа эталона в ответе.  
4. Лишний символ ответа.  
  
Алгоритм должен быть детерминированным.  
  
### 6.2. Модель операций  
  
```text  
equal  
substitute  
missing_in_answer  
extra_in_answer  
```  
  
Операции содержат диапазоны в нормализованном ответе и эталоне.  
  
Нормализатор также возвращает отображение нормализованных позиций на диапазоны оригинального текста. Отображение поддерживает преобразования одного символа в несколько, удаление символов и схлопывание пробелов.  
  
### 6.3. Представление  
  
При отличии от эталона CLI показывает две строки:  
  
```text  
Ваш ответ: ...  
Эталон:    ...  
```  
  
Правила:  
  
- совпадающие части — нейтральные;  
- заменённые символы — красные на обеих строках;  
- лишние символы ответа — красные в строке ответа;  
- пропущенные символы — красные в строке эталона;  
- участвующий в ошибке пробел показывается красным `_`;  
- игнорируемая пунктуация остаётся нейтральной;  
- отсутствие игнорируемой пунктуации не создаёт ошибку.  
  
При точном нормализованном совпадении достаточно показать оригинальный эталон без строки ответа.  
  
Если символ оригинала соответствует нескольким нормализованным позициям, он помечается ошибочным, когда хотя бы одна соответствующая позиция участвует в ошибке.  
  
Весь расчёт разметки выполняется в ядре. CLI получает готовые строки из сегментов с ролями и только оформляет их.  
  
Для терминала без поддержки цветов используется текстовое выделение ошибочных сегментов, например `⟦...⟧`.  
  
## 7. Жизненный цикл карточки  
  
Карточка находится в одном из трёх состояний:  
  
| Состояние | Условие |  
|---|---|  
| Новая | `first_show == true` |  
| Обучена, ещё не проверена | `first_show == false`, `fsrs_state == null` |  
| Проверенная | `first_show == false`, `fsrs_state != null` |  
  
### 7.1. Новая карточка  
  
При добавлении создаются:  
  
- `first_show = true`;  
- `fsrs_state = null`;  
- `introduced_at = null`;  
- `first_review_at = null`;  
- `due_at = null`;  
- пустая история и нулевые счётчики.  
  
Новая карточка не входит в множество due.  
  
### 7.2. Завершение обучающего показа  
  
После успешного ввода:  
  
- `first_show = false`;  
- `introduced_at = now`;  
- `first_review_at = now + initial_review_delay`;  
- FSRS остаётся неинициализированным.  
  
По умолчанию `initial_review_delay` равен 10 минутам.  
  
### 7.3. Первый проверочный показ  
  
Первый ответ после наступления `first_review_at` передаётся в `SchedulerPort.first_review()`.  
  
Сохраняются полученное состояние FSRS и `due_at`. `first_review_at` остаётся как историческое поле, но больше не участвует в выборе срока.  
  
### 7.4. Эффективный срок повторения  
  
```text  
новая карточка       → срока нет  
обучена без FSRS      → first_review_at  
карточка с FSRS       → due_at  
```  
  
Карточка является due, если её эффективный срок `<= now`.  
  
Сравнивается точное время, а не только календарная дата.  
  
## 8. Хранилище `user.json`  
  
### 8.1. Назначение  
  
Хранилище обеспечивает:  
  
- восстановление текущего расписания;  
- сохранение статистики за весь срок жизни карточки;  
- просмотр последних предъявлений;  
- объяснение последних автоматических оценок.  
  
Полная история обучения и достаточность данных для будущей оптимизации FSRS не гарантируются. Для этого потребуется отдельное расширение формата.  
  
### 8.2. Структура  
  
Концептуальная структура:  
  
```text  
UserData  
├── schema_version  
├── dataset_languages  
│   ├── native  
│   └── foreign  
├── scheduler_metadata  
│   ├── adapter_version  
│   ├── library_name  
│   ├── library_version  
│   └── state_format_version  
└── cards: dict[native_key, Card]  
```  
  
Карточка:  
  
```text  
Card  
├── native  
├── foreign_variants  
├── first_show  
├── fsrs_state | null  
├── created_at  
├── introduced_at | null  
├── first_review_at | null  
├── due_at | null  
├── last_presented_at | null  
├── last_reviewed_at | null  
├── last_chosen_reference | null  
├── counters  
│   ├── review_count  
│   ├── review_accepted_count  
│   ├── review_rejected_count  
│   ├── practice_count  
│   ├── practice_accepted_count  
│   └── practice_rejected_count  
└── history  
```  
  
`last_presented_at` обновляется при завершении первого обучения и при фиксации первого ответа обычного предъявления. Незавершённый показ без ответа дату не меняет.  
  
`last_reviewed_at` обновляется только при плановом повторении.  
  
### 8.3. Запись истории  
  
Одна запись соответствует первому ответу одного планового повторения или одной досрочной практики.  
  
Поля:  
  
- `event_type`: `review` или `practice`;  
- `shown_at`;  
- `answered_at`;  
- `user_input`;  
- `chosen_reference`;  
- `distance`;  
- `reference_length`;  
- `error_ratio`;  
- `comparison_category`;  
- `accepted`;  
- `fsrs_rating` — только для `review`, иначе `null`;  
- `scheduled_due_at_before`;  
- `scheduled_due_at_after`;  
- `comparison_policy_version`;  
- `normalization_policy_version`;  
- `grading_policy_snapshot` — параметры, необходимые для объяснения оценки;  
- `scheduler_review_log` — для `review`, иначе `null`.  
  
Исходный ответ сохраняется без обрезки, если он не превышает установленный лимит ввода.  
  
История — FIFO с настраиваемым лимитом, по умолчанию 30 записей на карточку.  
  
Первое обучение и перепечатывания не входят в FIFO. Они отражаются в журнале приложения.  
  
### 8.4. Счётчики  
  
`accepted` определяется условием завершения из §5.7 на момент ответа.  
  
Инварианты:  
  
```text  
review_count = review_accepted_count + review_rejected_count  
practice_count = practice_accepted_count + practice_rejected_count  
```  
  
Счётчики накопительные и не уменьшаются при удалении старых записей FIFO.  
  
Перепечатывания и первый обучающий показ в эти счётчики не входят.  
  
### 8.5. Проверка данных  
  
Проверяются:  
  
- версия схемы;  
- обязательные поля и типы;  
- timezone-aware timestamps UTC;  
- конечность числовых значений: `NaN` и бесконечности запрещены;  
- неотрицательные счётчики и их инварианты;  
- соответствие ключа нормализованному `native`;  
- непротиворечивость жизненного цикла;  
- корректность состояния планировщика;  
- согласованность сохранённого `due_at` со сроком в состоянии планировщика.  
  
Первая версия поддерживает только свою схему. Будущие миграции должны выполняться явно и с резервной копией.  
  
### 8.6. Даты  
  
Все даты сериализуются в ISO 8601 с суффиксом `Z`. Точность — до микросекунд либо меньшая единообразная точность, не теряющая данные выбранной библиотеки.  
  
Naive datetime запрещены.  
  
### 8.7. Атомарное сохранение  
  
1. Сериализовать весь новый документ.  
2. Создать временный файл в каталоге `user.json`.  
3. Записать данные.  
4. Выполнить `flush()` и `os.fsync()` файла.  
5. Выполнить `os.replace()`.  
6. На поддерживаемых платформах синхронизировать каталог для повышения устойчивости к сбою питания.  
  
При ошибке до замены исходный файл остаётся нетронутым. Временный файл по возможности удаляется.  
  
Если ошибка произошла после замены, приложение сообщает, что результат сохранения может быть неопределённым, и прекращает сессию без автоматического повторного применения review-события.  
  
Атомарная замена не является защитой от одновременной работы нескольких процессов. Параллельный запуск не поддерживается и может приводить к потере изменений. Блокировка файла в первой версии не требуется.  
  
### 8.8. Отсутствие, повреждение и несовместимость  
  
| Ситуация | Действие |  
|---|---|  
| Файл отсутствует | Создать новое хранилище |  
| Файл пуст или содержит повреждённый JSON | Предложить пересоздание |  
| Нарушена поддерживаемая схема | Предложить пересоздание |  
| Версия схемы или состояния планировщика не поддерживается | Выход без изменения файла |  
| Нет доступа, ошибка чтения | Выход без предложения пересоздания |  
  
Перед пересозданием повреждённого файла создаётся резервная копия его исходных байтов с уникальным именем.  
  
Если резервирование не удалось, пересоздание запрещено.  
  
Отказ от пересоздания завершает приложение без изменений.  
  
## 9. Синхронизация `phrases.txt` и `user.json`  
  
### 9.1. Правила  
  
| Изменение | Действие |  
|---|---|  
| Новый `native_key` | Создать новую карточку |  
| Отсутствующий в файле `native_key` | Запросить подтверждение удаления |  
| Изменение отображения native при том же ключе | Обновить текст без сброса прогресса |  
| Изменение ключа | Удаление старой и создание новой карточки |  
| Изменение вариантов перевода | Обновить варианты без сброса FSRS и `first_show` |  
| Перестановка вариантов | Обновить порядок без сброса прогресса |  
  
Старые записи истории сохраняют свои эталоны и не переписываются.  
  
Изменение смысла переводов может сделать прежнюю статистику менее релевантной. Приложение автоматически смысл не анализирует и прогресс не сбрасывает.  
  
### 9.2. Транзакционный сценарий  
  
1. Полностью загрузить и проверить фразы.  
2. Загрузить и проверить пользовательские данные.  
3. Построить план всех изменений без модификации исходного объекта.  
4. Если есть удаления — показать их количество, перечень и предупреждение о потере прогресса.  
5. Получить одно подтверждение на весь набор удалений.  
6. При отказе или завершении ввода — выйти без применения любых изменений синхронизации.  
7. При согласии — применить весь план к новому объекту данных.  
8. Сохранить его одним атомарным сохранением.  
9. Только после успеха перейти к сессии.  
  
Если изменений нет, повторное сохранение при старте не требуется.  
  
Штатные удаления не создают автоматический бэкап. Удаление безвозвратно с точки зрения приложения.  
  
Порядок карточек в текущей сессии берётся из `phrases.txt`, а не из порядка ключей JSON.  
  
### 9.3. Языковая пара  
  
В хранилище сохраняются идентификаторы языков набора.  
  
При несовпадении с конфигом приложение прекращает запуск и предлагает использовать другой `user.json` или явно исправить конфигурацию. Автоматически переносить прогресс между языковыми парами запрещено.  
  
Изменение только отображаемых названий языков не считается сменой пары.  
  
## 10. Выбор следующей карточки  
  
### 10.1. Множества  
  
Перед каждым выбором один раз считывается `now`.  
  
Карточки делятся на непересекающиеся группы:  
  
- `new` — `first_show == true`;  
- `due` — не новые, эффективный срок `<= now`;  
- `future` — не новые, эффективный срок `> now`.  
  
### 10.2. Алгоритм  
  
1. Если есть `due`, выбрать карточку с минимальным эффективным сроком. При равенстве — по порядку файла. Режим: `review`.  
2. Если есть `new` и `future`:  
   - с вероятностью `new_card_probability` выбрать первую новую;  
   - иначе выбрать ближайшую по сроку будущую карточку.  
3. Если есть только `new`, выбрать первую новую.  
4. Если есть только `future`, выбрать карточку по fallback-скорингу.  
5. Если карточек нет, завершить сессию.  
  
Новая карточка предъявляется в режиме первого обучения. Любая выбранная будущая карточка — в режиме `practice`.  
  
По умолчанию `new_card_probability = 0.5`. Лимита новых карточек за сессию нет.  
  
### 10.3. Защита от немедленного досрочного повтора  
  
При выборе `future` последняя предъявленная карточка исключается, если в этой группе есть хотя бы одна другая карточка.  
  
Защита не применяется к `due` и не изменяет сроки планировщика.  
  
Если карточка единственная, её повторная практика допускается.  
  
### 10.4. Fallback-скоринг  
  
Для карточки:  
  
```text  
error_score = доля записей с accepted == false в текущем FIFO  
age_score = min(max(now - last_presented_at, 0) / age_horizon, 1)  
score = error_weight * error_score + age_weight * age_score  
```  
  
При пустой истории `error_score = 0`. При отсутствии `last_presented_at` используется `created_at`.  
  
В скоринге участвуют `review` и `practice`.  
  
Выбирается максимальный `score`. При равенстве:  
  
1. Более ранний эффективный срок.  
2. Порядок в файле.  
  
Ошибочность является взвешенным фактором, а не абсолютным приоритетом.  
  
### 10.5. Уведомление о режиме  
  
При переходе из состояния «есть due» в состояние «due нет» показывается сообщение:  
  
> Срочных повторений нет. Продолжаем обучение и дополнительную практику.  
  
Если due отсутствуют с начала сессии, сообщение показывается один раз перед первой карточкой.  
  
Перед каждой карточкой оно не повторяется.  
  
## 11. Учебная сессия  
  
### 11.1. Фиксация режима  
  
Режим `review` или `practice` определяется при выборе карточки и не меняется во время её предъявления.  
  
Если срок наступил, пока пользователь отвечает на досрочную практику, этот ответ остаётся практикой. На следующем шаге карточка может оказаться due.  
  
### 11.2. Плановое повторение  
  
1. Зафиксировать `shown_at`.  
2. Показать native-фразу и запросить перевод.  
3. Обработать команду завершения, EOF или прерывание.  
4. При допустимом ответе зафиксировать `answered_at`.  
5. Выбрать эталон, вычислить категорию и рейтинг.  
6. Получить новое состояние от планировщика. Для первой проверки использовать `first_review()`.  
7. Подготовить обновлённые данные: FSRS, срок, счётчики, даты, эталон и запись истории.  
8. Атомарно сохранить данные.  
9. Только после успешного сохранения принять новое состояние в памяти и показать результат сравнения.  
10. Если условие завершения не достигнуто — перейти к перепечатыванию.  
11. Иначе выбрать следующую карточку.  
  
Время review-события FSRS равно `answered_at`.  
  
Пустой ответ является допустимым вводом и оценивается как `incorrect`.  
  
### 11.3. Досрочная практика  
  
Сценарий аналогичен плановому повторению, кроме следующего:  
  
- планировщик не вызывается;  
- `fsrs_state`, `due_at`, `first_review_at` и `last_reviewed_at` не изменяются;  
- обновляются счётчики практики и `last_presented_at`;  
- в FIFO записывается событие `practice` с `fsrs_rating = null`.  
  
Первый ответ практики сохраняется немедленно, до перепечатывания.  
  
### 11.4. Перепечатывание  
  
После непринятого первого ответа:  
  
1. Запросить перевод повторно.  
2. Снова выбрать ближайший вариант среди всех переводов.  
3. Показать результат сравнения.  
4. Повторять до выполнения условия §5.7 или завершения приложения.  
  
Перепечатывания:  
  
- не меняют FSRS;  
- не меняют счётчики, даты и FIFO;  
- не вызывают сохранение `user.json`;  
- записываются в лог согласно настройкам.  
  
Новые due-карточки не прерывают текущий цикл перепечатывания.  
  
### 11.5. Первый обучающий показ  
  
1. Показать native и первый foreign-вариант в оригинальном виде.  
2. Запросить перевод.  
3. Сравнить со всеми вариантами по общим правилам.  
4. При необходимости повторять ввод до выполнения условия завершения.  
5. После успешного ввода подготовить изменения из §7.2 и обновить `last_presented_at`.  
6. Сохранить данные.  
7. После успешного сохранения перейти к следующей карточке.  
  
Первое обучение не обновляет FSRS, счётчики review/practice и FIFO.  
  
До успешного завершения и сохранения `first_show` остаётся `true`.  
  
### 11.6. Ограничение ввода  
  
Максимальная длина сырого ответа задаётся в конфиге.  
  
Слишком длинный ввод:  
  
- не считается попыткой;  
- не оценивается;  
- не меняет данные;  
- вызывает сообщение и повторный запрос.  
  
В лог записываются факт превышения и длина, но не полный текст такого ввода.  
  
## 12. Команды и завершение  
  
- Единственная команда — `/exit`.  
- Проверка выполняется как `raw.strip().casefold() == "/exit"`.  
- Команда доступна во всех запросах ввода, включая стартовые подтверждения.  
- EOF и `Ctrl+C` означают корректное завершение, а не неправильный ответ.  
- Фраз с содержимым `/exit` не предполагается.  
  
При выходе:  
  
- ранее сохранённые события остаются сохранёнными;  
- обычный показ без первого ответа ничего не меняет;  
- выход из перепечатывания не отменяет сохранённый первый ответ;  
- незавершённое первое обучение не снимает `first_show`.  
  
Дополнительное сохранение при штатном выходе не требуется: все принятые изменения уже зафиксированы.  
  
Успешный штатный выход имеет код `0`. Ошибки конфигурации, данных, чтения или сохранения — ненулевой код.  
  
## 13. Конфигурация YAML  
  
### 13.1. Общие правила  
  
- Используется безопасная загрузка YAML.  
- Дублирующиеся ключи и неизвестные параметры считаются ошибками.  
- При отсутствии файла создаётся дефолтный конфиг.  
- Повреждённый существующий конфиг автоматически не перезаписывается.  
- Конфиг полностью проверяется до начала сессии.  
- Относительные пути разрешаются относительно каталога конфига.  
- Конфиг, файл фраз, пользовательские данные и лог должны иметь разные пути. При наличии файлов проверяется также совпадение через файловые ссылки, где это поддерживается.  
  
### 13.2. Обязательные группы параметров  
  
- Версия конфига.  
- Пути к фразам, пользовательским данным и логу.  
- Имя пользователя.  
- Идентификаторы и отображаемые названия языков.  
- Интерфейсные строки.  
- Политика нормализации и пунктуации.  
- Пороги сравнения и таблица рейтингов.  
- Условие завершения перепечатывания.  
- Параметры первого обучения.  
- Параметры выбора карточек и fallback.  
- Параметры FSRS.  
- Ограничения истории, текста и диагностик.  
- Параметры логирования.

```yaml  
  max_bytes: 5242880  
  backup_count: 3  
  log_raw_answers: false  
```  
  
Это фрагмент конфига. Сгенерированный файл также содержит интерфейсные строки и полную политику пунктуации.  
  
### 13.4. Валидация  
  
В частности, проверяются:  
  
- `0 < desired_retention < 1`;  
- `maximum_interval_days` — положительное целое;  
- `0 <= new_card_probability <= 1`;  
- `initial_review_delay_seconds > 0`;  
- `0 < partial_max_ratio <= 1`;  
- `near_max_edits >= 0`;  
- `near_min_reference_length > near_max_edits`;  
- веса fallback неотрицательны, их сумма положительна;  
- `age_horizon_seconds > 0`;  
- лимиты — положительные целые;  
- значения не являются `NaN` или бесконечностью;  
- параметры FSRS принимаются выбранной версией адаптера.  
  
Веса fallback при загрузке нормализуются так, чтобы их сумма была равна 1.  
  
### 13.5. Строки интерфейса  
  
Для каждого сообщения задаётся перечень допустимых плейсхолдеров.  
  
Разрешены только простые имена полей, например `{user}` и `{foreign}`. Обращения к атрибутам, индексам и произвольные выражения запрещены.  
  
Неизвестный плейсхолдер или ошибочный шаблон приводит к ошибке конфигурации до начала сессии.  
  
Ошибки загрузки самого конфига выводятся встроенными сообщениями, не зависящими от YAML.  
  
### 13.6. Изменение параметров  
  
- Изменение порогов сравнения и нормализации действует на будущие вводы.  
- Изменение параметров FSRS действует при следующих плановых повторениях.  
- Уже сохранённые сроки автоматически не пересчитываются.  
- Изменение параметров не изменяет прошлую историю.  
- При следующем сохранении история сокращается до актуального лимита, если он уменьшен.  
  
## 14. Логирование  
  
Используется `RotatingFileHandler`, UTF-8.  
  
Логируются структурированные события:  
  
- запуск и завершение;  
- версии приложения, схемы и планировщика;  
- результаты загрузки и валидации;  
- план и результат синхронизации;  
- резервирование и восстановление;  
- первый ответ каждого предъявления;  
- перепечатывания;  
- завершение первого обучения;  
- ошибки сравнения, планировщика и сохранения.  
  
Для ответов записываются режим, категория, расстояние, выбранный рейтинг при наличии и длительность обработки.  
  
Сырой текст ответа включается только при `log_raw_answers: true`. Это ограничение относится к логу; в FIFO первый ответ сохраняется согласно §8.3.  
  
Пользовательские строки экранируются, чтобы переводы строк и управляющие символы не нарушали структуру журнала.  
  
Сбой логирования не должен отменять успешно сохранённый ответ. Если лог недоступен, приложение показывает одно предупреждение и продолжает работу без файлового журнала. Ошибки сохранения `user.json` обрабатываются отдельно и являются фатальными для сессии.  
  
## 15. Поток выполнения при старте  
  
1. Загрузить или создать конфиг.  
2. Выполнить полную проверку конфига и путей.  
3. Инициализировать логирование.  
4. Показать приветствие и инструкцию по `/exit`, EOF и `Ctrl+C`.  
5. Прочитать и полностью проверить `phrases.txt`.  
6. При ошибках или пустом наборе завершиться без изменения прогресса.  
7. Загрузить `user.json`.  
8. При повреждении получить подтверждение, создать бэкап и подготовить новое хранилище.  
9. При несовместимости или ошибке доступа завершиться без изменения файла.  
10. Проверить языковую пару и состояние планировщика.  
11. Построить и подтвердить план синхронизации.  
12. Сохранить изменения синхронизации, если они есть.  
13. Показать легенду подсветки.  
14. Запустить учебную сессию.  
  
## 16. Производительность и эксплуатационные ограничения  
  
JSON-хранилище полностью перезаписывается после каждого зафиксированного первого ответа. Стоимость сохранения растёт с размером всего файла.  
  
Первая версия ориентирована на персональные наборы до 1000 карточек с историей до 30 записей на карточку. Большие наборы допускаются без гарантии интерактивной скорости.  
  
Для приёмки используется набор из 1000 карточек, до трёх переводов на карточку и текстов до 100 символов. На согласованной машине с локальным SSD целевая задержка от получения ответа до завершения сохранения и подготовки результата — не более одной секунды в обычных условиях. Характеристики машины фиксируются в отчёте проверки.  
  
Нормализованные эталоны вычисляются и кэшируются при загрузке набора. Для выбора ближайшего варианта достаточно вычислить расстояния; полный backtrace выполняется только для выбранного эталона.  
  
При недостаточной скорости хранения допускается последующая замена JSON на SQLite за тем же портом. Пакетное отложенное сохранение не допускается, поскольку нарушает требование немедленной фиксации.  
  
## 17. Приёмочные сценарии  
  
Проверки выполняются с дефолтной конфигурацией, если не указано иное.  
  
| Сценарий | Ожидаемый результат |  
|---|---|  
| Ответ отличается только регистром | `exact` |  
| Между словами введена табуляция | Считается пробелом |  
| Вместо `we'll` введено `well` | Не `exact` |  
| Ответ пуст после нормализации | `incorrect`, для review — `Again` |  
| Эталон состоит из одного символа, ответ пуст | Не принимается |  
| Вместо `He walks` введено `He walk` | Не принимается для завершения |  
| Два варианта равноудалены | Выбран первый по порядку файла |  
| Между попытками ближайший вариант изменился | Подсветка использует новый ближайший вариант |  
| В ответе есть лишний символ | Он выделен в строке ответа |  
| В ответе пропущен символ | Он выделен в строке эталона |  
| В ответе лишний или пропущенный пробел | Ошибочный пробел показан как `_` |  
| В эталоне есть игнорируемая пунктуация | Она не выделена как ошибка |  
| Первый обучающий показ завершён | Флаг снят, первая проверка назначена через 10 минут, FSRS отсутствует |  
| Выход во время первого обучения до успеха | Карточка остаётся новой |  
| Выход после ошибки в обычном review | Первый ответ и новое расписание уже сохранены |  
| Досрочная практика завершена | История практики сохранена, расписание FSRS не изменилось |  
| Срок наступил во время практики | Текущий ответ остаётся практикой |  
| Есть несколько due-карточек | Выбрана самая ранняя по сроку |  
| Есть только новые карточки | Выбрана первая по файлу |  
| Есть одна будущая карточка | Практика возможна, аварийного состояния нет |  
| Пустой `phrases.txt` | Выход без изменения `user.json` |  
| Найден дубликат native с другим регистром | Ошибка с номерами обеих строк |  
| Пользователь отказался от удаления | Вся синхронизация отменена, запуск завершён |  
| `/exit` введён при подтверждении | Завершение без применения плана |  
| Хранилище имеет более новую схему | Выход без пересоздания |  
| Хранилище недоступно по правам | Выход без предложения пересоздания |  
| Бэкап повреждённого файла не удался | Исходный файл не заменён |  
| Сохранение ответа не удалось | Сессия прекращена, следующий вопрос не показан |  
| Лог недоступен | Предупреждение, работа продолжается |  
| В конфиге неверный плейсхолдер | Ошибка до начала сессии |  
  
## 18. Ключевые инварианты  
  
- Идентификатор карточки — `native_key`, полученный по фиксированным правилам.  
- `phrases.txt` определяет состав активных карточек и варианты переводов.  
- Изменение ключа означает удаление и добавление; изменение переводов не сбрасывает прогресс.  
- Новые карточки не входят в due.  
- Первый обучающий показ назначает первую проверку, но не обновляет FSRS.  
- Только плановое повторение обновляет FSRS.  
- Досрочная практика сохраняется отдельно и не изменяет расписание.  
- Первый ответ обычного предъявления фиксирует результат; перепечатывания его не меняют.  
- Каждый ввод сравнивается с ближайшим вариантом; при равенстве побеждает первый.  
- Условие завершения перепечатывания отделено от рейтинга FSRS.  
- Пустой нормализованный ответ никогда не принимается.  
- Принятые изменения сохраняются до продолжения сессии.  
- Ошибка сохранения прекращает сессию.  
- Отказ от удаления отменяет весь план синхронизации.  
- Пустой файл фраз не удаляет прогресс.  
- Все сроки и сохраняемые даты используют UTC.  
- Due определяется точным сравнением срока с текущим временем.
