# Найденные ошибки проекта Flywheel

Анализ исходников `flywheel.py`, `data_level.py`, `system_level.py`, `ui_level.py` и `phrases.txt`.
Ошибки ниже воспроизведены запуском кода (Python 3.12.7, Windows, кодировка консоли по умолчанию `cp1251`).

---

## Критические

### 1. Поиск файлов забирает чужие данные из `C:\Work`

**Файл:** `system_level.py`, `FileOperations.find_or_create_file`  
**Строки:** 13–21

Если файла нет в текущей директории, код делает `os.walk(Path(__file__).parents[2])`.
Для `C:\Work\flywheel_temp\Code\system_level.py` это каталог `C:\Work`.

Дальше берётся **первый попавшийся** файл с таким именем в любом подпроекте.

Воспроизведение:

```text
find_or_create_file('repetitions.json')
→ C:\Work\github-pinned-repos\KaizenSpeech\Code\repetitions.json
```

Последствия:

- прогресс текущего проекта подменяется словарём другого репозитория;
- сохранение после сессии **перезапишет чужой** `repetitions.json`.

Искать нужно не выше корня текущего проекта (или не искать вообще, а создавать файл рядом с приложением).

---

### 2. Падение на испанских буквах в консоли Windows

**Файл:** `ui_level.py` (`print` ответа), `phrases.txt` (слова с `í`, `é`, `¿`, `¡`)

`sys.stdout.encoding` в этой среде — `cp1251`, `utf8_mode = 0`.
`just_fix_windows_console()` включает ANSI-цвета, но **не** UTF-8.

Печать эталонной фразы вроде `Sí` даёт:

```text
UnicodeEncodeError: 'charmap' codec can't encode character '\xed'
```

Сессия обрывается. Это не Ctrl+C, поэтому `except KeyboardInterrupt` в `flywheel.py` исключение не ловит. Если ошибка случится внутри `user_session` до возврата в цикл, попытка может не попасть на диск.

Нужно задать UTF-8 для stdout/stderr при старте (например `sys.stdout.reconfigure(encoding='utf-8')`) или печатать через безопасный слой.

---

### 3. После ошибки SuperMemo-2 не ставит карточку на повтор

**Файл:** `data_level.py`, `_supermemo2`  
**Строки:** 251–261

При неверном ответе обнуляется только `repetition_number`. Поле `time_to_repeat` **не меняется**.

Проверка: зрелая карточка с датой через 20 дней после провала всё ещё имеет ту же дату.

По SuperMemo-2 неудачный ответ должен сбросить интервал (карточка снова due сразу / на следующий день). Сейчас «проваленная» фраза исчезает из очереди до старой будущей даты.

Это усиливается логикой `determine_next_phrase`: если есть новые карточки, проваленная с будущей датой **не будет выбрана**.

## Серьёзные

### 4. Интервал SuperMemo-2 не растёт после 3-го успеха

**Файл:** `data_level.py`, `_supermemo2`  
**Строки:** 256–258

Классическая формула:

- `I(1) = 1` день
- `I(2) = 6` дней
- `I(n) = I(n-1) * EF` при `n > 2`

В коде для любого `repetition_number >= 2` всегда:

```python
timedelta(days=6 * repetition['easiness_factor'])
```

Фактические интервалы при идеальных ответах:

| Успех | Ожидание SM-2 | Факт |
|------|----------------|------|
| 1 | ~1 день | ~1 |
| 2 | ~6 дней | ~6 |
| 3 | ~6×EF ≈ 15–16 | ~16 |
| 4 | предыдущий × EF ≈ 40+ | **~16** |
| 5 | ещё × EF | **~17** |

Интервал застывает около `6 * EF`. Повторения не разрежаются.

---

### 5. Короткий правильный ответ красится как полностью неверный

**Файл:** `data_level.py`, `find_user_mistakes`  
**Строки:** 219–220

Совпадения короче 3 символов игнорируются:

```python
if n >= 3:
```

Проверка:

```text
'No' vs 'No'  → [False, False]
'OK' vs 'OK'  → [False, False]
'Sí' vs 'Sí'  → [False, False]
```

В `phrases.txt` много коротких фраз (`Yes || Que sí`, `Not me || Yo no`, `And you || Y tú`).

Если сходство попадает в диапазон `0.65 … 0.99`, UI рисует эталон целиком красным, хотя пользователь почти угадал. Для идеального совпадения (Jaro = 1.0) ветка «Correct!» diff не использует — баг проявляется на близких коротких ответах.

---

### 6. Диакритика не учитывается при сравнении

**Файл:** `data_level.py`, `find_max_string_similarity`

```text
'si' vs 'sí' → similarity ≈ 0.667
```

Порог «почти правильно» — `0.97`, «неплохо» — `0.65`. Ответ без ударения едва проходит как mediocre, хотя для испанского это типичная опечатка.

Вместе с ошибкой №5 подсветка тоже бесполезна: оба символа `sí` помечаются как ошибки.

Имеет смысл нормализовать Unicode (NFD) и сравнивать без combining-знаков, либо считать отсутствие акцента лёгкой ошибкой.

---

### 7. Пустой/битый JSON каждый запуск выглядит как ошибка и обнуляет прогресс

**Файл:** `system_level.py`, `read_json_from_file`; `flywheel.py` строки 14–22

`find_or_create_file` создаёт **пустой** файл. Сразу после этого `json.load` падает:

```text
Cannot open or parse ... JSONDecodeError('Expecting value: line 1 column 1 (char 0)')
```

Это происходит на первом запуске для `repetitions.json` и каждый раз для пустого `user_statistics.txt`.

Если уже существующий `repetitions.json` повреждён, функция молча возвращает `{}`. Затем `merge` создаёт карточки заново с `repetition_number = 0` — история повторений теряется без явного предупреждения о потере данных.

Пустой файл лучше считать валидным `{}`, а повреждённый — останавливать работу, не затирая оригинал.

---

### 8. `read_json_from_file` может вернуть не dict

**Файл:** `system_level.py`, `read_json_from_file`; `data_level.py`, `data_assessment` / `update_statistics`

Если в файле JSON-массив, возвращается `list`.

- для повторений `data_assessment` делает `sys.exit()` **с кодом 0**;
- для статистики проверки типа нет — `update_statistics` падает с `TypeError: list indices must be integers or slices, not str`.

Нужна проверка `isinstance(..., dict)` на уровне чтения файла.

## Средние

### 9. `sys.exit()` без кода ошибки

**Файлы:** `data_level.py` строки 26, 30; `flywheel.py` строка 73

`sys.exit()` ≡ код 0 (успех). Скрипт, обёртка или CI не увидят аварию.

Для сбоя сохранения уже используется `sys.exit(1)` — поведение нужно унифицировать.

`data_assessment` ещё и завершает процесс из библиотечной функции вместо возврата ошибки.

---

### 10. Пустая очередь фраз даёт KeyError

**Файл:** `data_level.py`, `determine_next_phrase`; `flywheel.py` строка 38

На пустом словаре функция возвращает `''`, затем:

```python
repetitions[current_phrase]  # KeyError
```

Сейчас это частично закрыто проверкой «оба словаря пустые», но любой путь с пустым `repetitions` после merge (или битые записи без `attempts` / с кривой датой) роняет сессию:

```text
ValueError: time data 'bad-date' does not match format '%Y.%m.%d %H:%M:%S'
KeyError: 'attempts'
```

Нет защиты от повреждённых карточек.


---

### 11. Подсветка ошибок теряет пробелы и может дать IndexError

**Файл:** `ui_level.py`, `_print_colored_diff`

- ведущий/хвостовой пробел при `correction[i] == False` не печатается вообще (`i-1` / `i+1` вне диапазона);
- если карта короче эталона — `IndexError: list index out of range`.

Для фраз вроде `Yes, yes || Si, si` визуально пропадают пробелы.

---

### 12. Сообщение merge при пустом `phrases.txt` вводит в заблуждение

**Файл:** `data_level.py`, `merge` строки 42–46

Пустой словарь фраз намеренно не чистит повторения (это правильно), но возвращает `'No new phrases'`. Пользователь не понимает, что файл фраз не прочитан и синхронизация не выполнялась.

## Замечания (не дефекты логики, но стоит поправить)

| Что | Где | Комментарий |
|-----|-----|-------------|
| Нет `requirements.txt` | корень проекта | Зависимости `jellyfish` и `colorama` нигде не зафиксированы |
| `user_statistics.txt` хранит JSON | `flywheel.py:11` | Расширение `.txt` при `json.load`/`json.dump` |
| Опечатка `delimeter` | `phrases.txt` | В комментарии к формату |
| Комментарий «english phrase» при испанском UI | `phrases.txt`, `ui_level.py:15` | Словарь английский→испанский, в коде поля названы `english_*` |
| Аннотация `str \| List[str]` | `data_level.py:156` | Предупреждение инспекции PyCharm «Invalid type annotation» |
| Тень имени `ch` | `data_level.py:215` | `lambda ch` перекрывает переменную цикла |

## Что выглядит исправленным / сделано хорошо

- Атомарная запись JSON через временный файл + `os.replace` + `fsync` — прерванное сохранение не портит файл.
- Пустой `phrases.txt` больше не вычищает все повторения (есть явный guard в `merge`).
- Слишком длинные фразы (`> 300`) отбрасываются при чтении.
- `/exit` и Ctrl+C завершают сессию, финальный save пытается записать данные.
- После неудачной записи сессия не продолжается молча.

---

## Приоритет исправлений

1. Ограничить поиск файлов текущим проектом (ошибка 1).
2. Включить UTF-8 для консоли (ошибка 2).
3. Починить SuperMemo-2: сброс `time_to_repeat` при ошибке и рост интервала `I(n-1)*EF` (ошибки 3–4).
4. Сравнение и подсветка коротких/акцентированных фраз (ошибки 5–6).
5. Корректная обработка пустого и битого JSON (ошибки 7–8, 10).
